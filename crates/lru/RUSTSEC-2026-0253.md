# RUSTSEC-2026-0253

## Summary
LruCache::pop() in lru 0.12.5 is not panic-safe. If Drop impl of stored value panics during pop(), internal pointers become dangling leading to use-after-free.

## Impact
Use-after-free -> potential memory corruption in any project using lru 0.12.5 including bnn-code.

## Affected versions
0.12.5, 0.16.x

## Fixed versions
0.18.2

## References
- https://rustsec.org/advisories/RUSTSEC-2026-0253
- https://github.com/jeromefroe/lru-rs

## Fix
Update `lru` crate to `>=0.18.2` or update `bnn-code` dependency.

## Proof
From bnn-code: `cargo audit` before fix showed warnings for RUSTSEC-2026-0253 and RUSTSEC-2026-0002. After updating lru to 0.18.2, both warnings are resolved.
